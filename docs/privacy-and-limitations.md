# プライバシーと制約

## データの取扱い

論文プロジェクト，入力内容，履歴，設定は，最初に利用中のブラウザー内ストレージへ保存される．クラウド同期が未設定，未ログイン，または利用者が同期を実行していない状態では，入力した研究情報を外部へ送信しない．

章立て，博士論文全体の中心研究課題，各章の「論証契約」も論文プロジェクトの一部であり，同じ保存規則に従う．論証契約には仮説，実験・解析，結果，限界など未発表情報が入り得る．通常は端末内に保存され，クラウド同期を有効化してログインし，そのプロジェクトの同期を明示的に実行した場合だけSupabaseへ送信される．JSON／ZIPバックアップには復元用データとして含まれるため，バックアップ共有時も本文と同じ機密情報として扱う．

任意のクラウド同期を有効にすると，利用者が選んだプロジェクト本体をSupabase PostgreSQLへ，添付ファイルをSupabase private Storageへ送信する．ログインだけで端末内プロジェクトを自動送信しない．Supabase上のデータはエンドツーエンド暗号化ではないため，未発表情報，個人情報，医療情報，輸出管理対象などを扱う前に所属組織の規程を確認する必要がある．

JSON，ZIP，Typstソース，印刷PDFとして書き出したファイルは，利用者が選んだ保存先に置かれる．共有PCでは，ブラウザー内データと書き出したファイルの両方を適切に管理する必要がある．

## 保存領域の境界

端末内の保存内容は次の間で自動共有されない．設定済みのHTTPS版で同じアカウントへログインし，明示的に同期したプロジェクトだけが端末間で共有される．

- `file://` で開いたローカル版とHTTPSのGitHub Pages版
- 異なるブラウザーまたはブラウザープロファイル
- 異なる端末
- 通常ウィンドウとプライベートブラウジング

ブラウザー内ストレージの容量と `file://` での挙動はブラウザー実装や設定に依存する．ブラウザーデータの削除，プロファイルの初期化，ストレージ容量不足によって内容を失う可能性がある．重要な作業ではバックアップを定期的に作成する．添付ファイルを含む完全な復元にはZIPを使い，JSONは本文・設定のみとする．バックアップの上限は100 MBであり，添付本体が保存領域から失われている場合はZIP作成を中止して通知する．

## LLMとAPIキー

本アプリは，APIキーを必要とするライブLLM連携を提供しない．静的ページのHTMLやJavaScriptへ置いたキーは利用者から確認でき，安全に秘匿できないためである．原稿作成支援と不足項目の検出は，外部APIを必要としないルールベース処理を基本とする．

AI作業台は，英文変換，模擬査読，内容補強，章の深掘り・肉付け，校正，文献調査の指示文をブラウザー内で組み立てるだけである．Ollama，Qwen，Codex，Claude Codeその他のサービスやプログラムを自動起動せず，プロンプトや原稿を送信しない．対象範囲を限定した場合は，選択外の本文，著者，参考文献，研究情報を指示文へ混入させない．章の深掘りでは，選んだ章の本文・論証契約と全体の中心研究課題だけを含め，別章や添付を自動で含めない．コピーまたは保存したプロンプトをどこで使うかは利用者が選び，使用先のプライバシー条件を別途確認する必要がある．未公開情報や個人情報を外部サービスへ貼り付ける前に，必ず内容を確認する．

章の論証契約とAIが返した肉付け案は，法的な契約，査読，研究倫理上の承認，検証済み証拠ではない．入力欄を埋めても主張・仮説・解析の正しさは確認されず，AI向けプロンプトも不足情報を事実へ変換しない．著者が原データ，解析手順，確認済み文献と照合し，採用範囲を判断する必要がある．

LLMなど別の外部サービスを将来追加する場合も，利用者が明示的に有効化すること，送信内容と送信先を事前表示すること，秘密情報を静的資産へ保存しないことを必須とする．

## ログインとクラウド同期

クラウド同期はGitHub PagesなどのHTTPS版だけで使用する．メールOTPを使い，パスワードを本アプリへ保存しない．認証セッションは長期の端末保存を避け，ブラウザーのセッション領域へ保持する．共有端末では作業後にログアウトし，端末内へ取り込んだ原稿も残ることに注意する．ログアウトはブラウザー内の原稿を暗号化または削除する機能ではない．

ブラウザーへ設定するSupabase Publishable keyは公開用の識別情報であり，秘密鍵ではない．実際のアクセス制御はPostgreSQLとStorageのRLSで本人に限定する．Secret key，`service_role` key，データベースパスワードはHTMLやJavaScriptへ保存してはならない．

同期はサーバー管理の版番号を使い，別端末の更新を検出した場合は上書きを停止する．データベース側はpayloadの`schemaVersion`も比較し，既存の形式より古いクライアントからの更新を競合として停止する．これは章立てや論証契約など新しいフィールドが古いブラウザーキャッシュから消されることを防ぐためである．通信失敗，ブラウザー終了，Storage容量不足などにより同期が完了しない可能性があるため，「端末保存済み」と「クラウド同期済み」を区別し，ZIPバックアップも継続する．

GitHub Pagesでは`USER.github.io`の後ろのリポジトリパスが違っても同一オリジンであり，IndexedDBを共有する．同じホスト上の別Pagesサイトを信頼できない場合，機密原稿には専用カスタムドメインまたは専用GitHubアカウント／Organizationを使用する．ブラウザーのサイトデータ削除もオリジン単位で別Pagesアプリへ影響し得るため，専用ドメインでない場合は削除対象を確認する．

初期版のクラウド添付は，上書きと利用者操作による削除を許可しない不変オブジェクトである．原稿から添付メタデータを外してもStorage本体は自動削除されない．機密ファイルをクラウドから消去する必要がある場合，バックアップと対象所有者・`cloud_id`を確認したうえでSupabase管理者が処理する．

## ファイル

ブラウザーは，利用者が選択またはダウンロードを許可したファイルだけを扱う．アップロードされたファイルについて，名前，拡張子，サイズだけで安全性を保証することはできない．信頼できないファイルを開かず，バックアップZIPを共有するときは内容を確認する．

登録用テンプレートは最大512 KiBのテキスト形式に限定し，スクリプトやHTMLを実行しない．見出しなどを安全なテキストへ正規化し，元ファイルの本文は保存しない．PDFとDOCXは登録対象外である．登録した構成定義はこのブラウザーの設定へ保存され，その構成で作成したプロジェクトにも必要な定義を埋め込む．

## PDFとTypst

PDFはブラウザーの印刷機能から「PDFに保存」を選んで作成する．ページサイズ，改ページ，フォント，余白はブラウザーとOSによって異なる場合がある．投稿先の要件に合うことを利用者が最終確認する必要がある．

ブラウザー印刷へ直接配置できる図表はPNG，JPEG，SVGとする．PDF形式の添付を図表として指定した場合は印刷を中止して通知するため，PNG/SVGへ変換するかTypst ZIPを利用する．

Typstソースは書き出せるが，ブラウザーからTypst CLIを実行することはできない．Typstコンパイルが必要な場合は，書き出したファイルを別のTypst環境で使用する．

章の論証契約は内部の構成メモであり，章本文，Typstソース，ブラウザー印刷PDFへ自動挿入しない．本文へ採用する場合は，根拠を確認したうえで著者が章本文を編集する．

## 機能上の制約

- Realtime共同編集，複数人での共有編集，自動マージは行わない．端末間同期は同一アカウントによる明示操作である．
- `file://`版ではログインとクラウド同期を使わず，端末内保存とバックアップだけを利用する．
- Pythonやネイティブコマンドをブラウザーから実行しない．
- AIの回答自体は生成・取得しない．AI作業台が作るのは利用者確認用のプロンプトである．
- 章の論証契約は主張と根拠の整理を支援するが，内容の妥当性，証拠能力，章間の論理的一貫性を保証しない．
- テンプレートの自動解釈は見出し・言語・段組などの推定であり，投稿規程への完全な適合を保証しない．
- PDF印刷結果は専用組版エンジンの結果と完全には一致しない．
- 生成内容，数値，引用，参考文献の正しさを保証しない．投稿前に必ず利用者が確認する．
- ブラウザーの互換性やセキュリティ設定により，一部の保存・ダウンロード機能が制限される場合がある．
