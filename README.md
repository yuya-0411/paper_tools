# paper_tools

`paper_tools` は，論文の構成，本文，助言，Typstソースをブラウザー内で作成・保存する静的Webアプリである．Python，Node.js，パッケージインストール，ビルド，ローカルサーバーは不要である．

## すぐに使う

### PC上で使う

1. リポジトリをZIPでダウンロードして展開する．
2. ルートの `index.html` をダブルクリックする．
3. ブラウザーで論文プロジェクトを作成する．

環境構築コマンドはない．`index.html` を開いた時点で利用を開始できる．

## 主な機能

- 5段階の新規作成画面と，目的別の8種類のテンプレート．
- 4項目だけで始められる簡易入力と，実験条件・評価指標まで扱う詳細入力．
- 入力済みの事実だけを使う決定論的な草稿生成と，不足情報・図表・実験・引用の診断．
- セクション本文，セクション別指示，著者，参考文献，図・表・データのブラウザー内編集．
- BibTeXの読込み，Typst・BibTeX・Hayagriva YAMLの書出し．
- ブラウザー印刷によるPDF保存，JSONバックアップ，添付を含むZIPバックアップと復元．

外部AIや外部APIへ接続せず，入力内容を端末内で処理する．生成器は未入力の数値や参考文献を補完せず，確認が必要な箇所を明示する．

### GitHub Pagesで使う

GitHub Pagesを有効にした場合は，公開されたURLをブラウザーで開くだけで利用できる．初回は次の順で手動公開する．

1. GitHubのリポジトリで `Settings` → `Pages` を開く．
2. `Build and deployment` の `Source` を `GitHub Actions` にする．
3. `Actions` → `Deploy static app to Pages` → `Run workflow` を開く．
4. 公開対象のブランチ（通常は `main`）を選び，`Run workflow` を押す．
5. 完了後，ワークフローまたは `Settings` → `Pages` に表示されたURLを開く．

このリポジトリにはPages配信用ワークフローを含むが，本READMEはデプロイ済みであることを保証しない．

## データ保存とバックアップ

編集内容と設定は，利用中のブラウザー内ストレージへ保存される．サーバーへ自動送信されない．重要な原稿は，画面からバックアップを定期的に保存すること．本文・設定だけならJSON，添付した図・データを含む完全な復元にはZIPを使う．バックアップの上限は100 MBであり，添付本体がブラウザー内に残っていない場合は不完全なZIPを作らず，画面にエラーを表示する．Typstソースは `.typ` または添付込みZIPとして書き出せる．

次の環境は別々の保存領域として扱われ，内容は自動同期されない．

- ダブルクリックで開いた `file://` 版とGitHub Pages版
- 異なるブラウザー，ブラウザープロファイル，PC
- 通常ウィンドウとプライベートブラウジング

別の環境へ移る前にバックアップを作成する．JSONとZIPはどちらも「バックアップを読み込む」から復元できるが，JSONに添付ファイル本体は含まれない．ZIPでは添付した図・データも再接続される．ブラウザーデータを消去すると，未バックアップの内容は失われる可能性がある．

## PDFとTypst

- 画面の原稿をPDFにする場合は，ブラウザーの印刷機能から「PDFに保存」を選ぶ．
- ブラウザー印刷へ埋め込む図表はPNG，JPEG，SVGを使う．PDF形式の図表はPNG/SVGへ変換するか，Typst ZIPから組版する．
- Typstソースは書き出せるが，本アプリはTypstコンパイラーを実行しない．必要に応じて書き出した `.typ` を別のTypst環境でコンパイルする．

## プライバシー

主要機能は静的ファイルだけで動作し，論文データを処理するバックエンドを持たない．公開された静的JavaScriptではAPIキーを安全に秘匿できないため，OpenAI互換APIなどへのライブ接続とAPIキー保存は実装しない．LLMなしで使えるルールベース支援を基本とする．

詳しくは [プライバシーと制約](docs/privacy-and-limitations.md) を参照する．

## GitHub Pages

`.github/workflows/pages.yml` は，将来利用するときに手動実行してPagesへ配信する．利用前にGitHubのSettingsからPagesのSourceを「GitHub Actions」に設定する．現時点ではpushだけで勝手に公開しない．ワークフローにアプリのビルド処理はなく，静的ファイルをそのまま配信する．

## 開発

HTML，CSS，JavaScriptを編集し，`index.html`を再読込して確認する．実行環境の構築コマンドはない．設計は [アーキテクチャ](docs/architecture.md) を参照する．

ブラウザーだけでテストする場合は，`tests/index.html` をダブルクリックする．GitHub Actionsでは同じロジックテストをNode.jsで実行するが，アプリの利用者にNode.jsは不要である．
